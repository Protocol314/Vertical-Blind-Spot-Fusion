# 18. 단계별 수락 기준 및 최종 Definition of Done

## Gate G0 — 환경 준비

- [ ] Python 버전/OS/ROS2/드라이버/GPU 상태 확인 및 로그.
- [ ] 기존 Pi 프로젝트나 `/scan` 출력을 삭제/수정하지 않음.
- [ ] 하드웨어 없는 테스트 실행 가능; 모델 미다운로드 시 graceful skip 또는 stub.
- [ ] `README`의 재현 명령이 실제 개발자 환경과 일치.

## Gate G1 — 센서 결합(반드시 달성)

- [ ] 실제 또는 합성 `/scan`과 영상 탐지의 timestamp 고정·유지.
- [ ] camera↔lidar 좌표계 변환을 독립 표적으로 검증하고 보정 파일 저장.
- [ ] `bbox` 내부 배경점 반사로 인한 잘못된 객체 거리 할당 방지(고장 시험 F06).
- [ ] LiDAR 반사가 없는 영상 물체가 **출력에서 삭제되지 않으며 `range=null`**.
- [ ] LiDAR만 보이는 장애물도 보존되고, camera-only와 구별 가능.
- [ ] `/scan`은 결합 전에 비해 **실측 의미가 변형되지 않음**.

## Gate G2 — 모델·평가

- [ ] B0~B4 동일 세션/GT로 재생 비교 가능.
- [ ] 융합 모델의 학습/검증/시험 데이터가 session 단위로 분리됨.
- [ ] 모델 가중치/전처리/feature order/threshold/seed/hardware hash 기록.
- [ ] 실측 객체별 ground-truth 위험 이벤트 생성(학습에 사용한 예측이 정답 아님).
- [ ] 아래/위/일반 스캔 조건별 FN, Recall, FA/min, 잘못된 거리 대응 통계 산출.
- [ ] YOLO runtime, fusion runtime, e2e age의 p50/p95/p99와 drop 비율 기록.
- [ ] B4 개선이 없다면 결과를 그대로 보고하고 왜 그런지 분석.

## Gate G3 — 시연·인수

- [ ] 원본 입력과 5종 결과를 나란히 재생하는 데모/녹화.
- [ ] 최소 3가지 실패 사례(벽-박스 오인, 카메라 dropout, 오래된 프레임)가 재현됨.
- [ ] 다른 개발자가 clean clone에서 설치/fixture replay/평가 가능(가중치·데이터 미포함 시 구득 절차 문서화).
- [ ] 보정·시간·장치·라이선스·사람/도로 적용 제한이 보고서에 포함.
- [ ] 실제로 측정되지 않은 수치를 논문의 결과처럼 사용하지 않음.

## 정량 목표와 성공 판정

- **달성 기준을 사전 등록할 수 있으나**, 장비·주행 속도·현장 통계가 없으므로 포괄적인 사각지대 미탐률 숫자를 지금 강제하지 않는다.
- 주요 성공판정: H1의 개선 여부, 동일 recall 비교의 H2, 지연 목표 H3, 잘못된 거리 대응 감소 H4.
- 후처리 p95 5ms, 10Hz 수준 갱신은 **전형적인 C1과 프로젝트 자원에 맞춘 목표값**이지 보장 성능이 아니다.
- 시험에 실패해도 정량적 실패 원인·교란·한계를 재현하면 연구 증거로 보존한다.
